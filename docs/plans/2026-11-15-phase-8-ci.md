# Phase 8 — GitHub Actions CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every PR to `dev` or `main` and every push to `dev` or `main` runs lint, format, build, unit and integration tests with coverage, the compose smoke test and the four contract suites, SonarCloud analysis, and a multi-arch (amd64 + arm64) Docker image build per changed app; pushes to `main` (production) publish the images to GHCR.

**Architecture:** Two workflows. `ci.yml` is the quality gate (verify → unit/int tests with coverage → e2e on the compose stack → Sonar). `images.yml` decides which images changed with path filters, builds each changed image natively on `ubuntu-24.04` and `ubuntu-24.04-arm`, pushes by digest, and merges a multi-arch manifest on `main`. Coverage is opt-in through one env var (`CI_COVERAGE=1`) so local `pnpm test` stays unchanged.

**Tech Stack:** GitHub Actions, pnpm 10.34.9 + Turborepo 2, Node 26, .NET SDK 10.0.404, Jest 30 coverage, `@vitest/coverage-v8`, `coverlet.collector`, `dotnet-sonarscanner`, SonarCloud, Docker Buildx, GHCR.

**Spec:** `docs/spec.md` (§9 Deployment, §11 "CI: lint, build, test, Docker image; bonus Sonar, coverage → Phase 8"), `docs/PROMPT.md` Phase 8, `docs/engineering/initial-assessment.md` (M6, M7, L16).

**Branch:** `phase-8-ci`, created from `dev`. Merges to `dev`; Phase 8 ends with the first release PR `dev` → `main`.

## Decisions taken with the user (2026-11-15)

1. Repo is public; the user creates the SonarCloud organization, both projects and the `SONAR_TOKEN` repo secret. The Sonar job skips cleanly when the secret is absent (fork PRs, before setup).
2. Coverage from unit AND integration runs. New test-only deps: `@vitest/coverage-v8` (web), `coverlet.collector` (.NET), plus the `dotnet-sonarscanner` .NET local tool. ADR-0025 records them.
3. arm64 built on native `ubuntu-24.04-arm` runners (free for public repos), pushed by digest, merged into one manifest. This also verifies the .NET image on arm64 (carry-forward item).
4. Smoke + contract suites run on every PR and every push to `dev` and `main`.
5. `main` is the production branch and the GitHub default branch. Flow: phase/feature branch → PR to `dev` (integration) → release PR `dev` → `main`. Only `main` publishes images (Phase 9 deploys from them). Before execution the user creates `main` from `dev`, pushes it, sets it as the default branch, and protects it (required checks = the `ci.yml` jobs, PR required).

Defaults decided in this plan (recorded in ADR-0025): triggers `pull_request` → `dev`/`main`, `push` → `dev`/`main`, `workflow_dispatch` (images: input `all` builds every image); GHCR push only on push to `main` and dispatch from `main` (PRs and `dev` build without pushing, so arm64 is still verified before release); SonarCloud main branch = `main`, `dev` analyzed as a long-lived branch; NuGet audit fails CI on High/Critical only (NU1901/NU1902 stay warnings); every third-party action pinned to a full commit SHA with a `# vX.Y.Z` comment; two SonarCloud projects because the generic scanner cannot analyze C#.

## Global Constraints

- Never commit secrets; never read or print `infra/.env` (CI generates its own with `setup-local.mjs`).
- Node from `.nvmrc` (26); pnpm `10.34.9` (root `packageManager`); .NET SDK from `apps/ticket-service-dotnet/global.json` (10.0.404).
- No dependency beyond the three named in Decision 2 and the GitHub Actions listed in Task 3/4 without asking.
- Every action pinned to a commit SHA of a release at least 14 days old; comment the version.
- Workflow `permissions:` default `contents: read`; only `images.yml` publish jobs get `packages: write`.
- Image names: `ghcr.io/zainelabdeen/e-ticketing/<image>` (GHCR needs a lowercase owner). Tags: `latest` and `sha-<7-char sha>`, published from `main` only.
- The deployed Ticket Service image is the .NET one and is named `ticket-service`. The NestJS reference Ticket Service gets no image.
- `infra/scripts/smoke.sh` runs `down -v`; fine on a CI runner, never run it locally without asking.
- Contract suite order: ticket → payment → ledger → gateway (ticket drains VIP quota).
- Local commands keep working unchanged: `pnpm test`, `pnpm test:int` without `CI_COVERAGE` produce no coverage output.
- Commits: conventional, small, end with the `Co-Authored-By` line from the session.

## Review Focus

1. **Sonar shows 0 % coverage because lcov/opencover paths do not resolve.** Jest writes absolute `SF:` paths, Vitest relative ones; the Sonar job runs in a different job/checkout. Expect: Sonar log line `Could not resolve 0 file paths` (or no such warning). Task 3 Step 6 checks it on the first real run.
2. **Turbo strict env mode drops `CI_COVERAGE`.** Turbo 2 filters undeclared env vars, so coverage silently never runs. Expect: lcov files appear when `CI_COVERAGE=1`. Task 1 Step 2 tests exactly this through `pnpm test`, not through jest directly.
3. **A shared-package change (e.g. `packages/nest-common`, `pnpm-lock.yaml`) does not rebuild dependent images.** Expect: changing a shared path selects every Node image. Task 4 Step 2 tests the filter map.
4. **Sonar step fails a fork PR or a repo without `SONAR_TOKEN`.** Expect: Sonar steps skipped, job green. Task 3 Step 5 asserts the `if:` guard with actionlint + a dispatch run before the secret exists.
5. **`verify-db.sh` breaks the e2e job once a second migration lands (M6).** Expect: passes with N migration dirs per schema. Task 2 Step 2 tests it with a fake second directory count.
